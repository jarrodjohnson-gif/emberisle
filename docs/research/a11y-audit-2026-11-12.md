# Accessibility and Keyboard Navigation Audit

- date: 2026-11-12
- agent: builder-a11y
- lane: hud (tier 3)
- targets: `SeatPublicGains.tsx`, `TradePanel.tsx`

## Overview
This audit examines accessibility and keyboard navigation for recently merged HUD components.
It inspects `SeatPublicGains.tsx`, `TradePanel.tsx`, `TradeResource.tsx`, and `SeatNeeds.tsx`.
The audit verifies roles, labels, live regions, tab indices, and focus rings.
All automated focus and contrast proofs passed cleanly.

## 1. SeatPublicGains.tsx Audit
`SeatPublicGains` renders public roll and trade goods deltas under player seats.
The component renders into the DOM through React portals attached to seat cards.

### ARIA Attributes and Semantics
- **Role:** The container span specifies `role="status"`.
- ARIA specifications assign `role="status"` an implicit polite live region.
- **aria-label:** The tag carries `aria-label={`${name}: ${label}`}`.
- Example output includes `"Joshua: +2 Wheat"` and `"Joshua: +1 Wood, −1 Wheat"`.
- **aria-hidden:** Inner pill spans set `aria-hidden="true"`.
- This prevents screen readers from announcing fragmented icons and signed numerals twice.
- **aria-live:** `role="status"` provides implicit `aria-live="polite"` without interrupting user input.

### TabIndex and Focus Behavior
- The component sets no `tabIndex`.
- The container has `pointer-events: none` in CSS.
- The cue never captures pointer clicks or keyboard focus.
- Seat buttons use `position: relative` and `z-index: 1`.
- Keyboard users can reach and activate the underlying seat button without interference.

### Motion and Lifetime
- The cue holds for 2.5 seconds before fading.
- CSS slide and opacity transitions disable under `prefers-reduced-motion: reduce`.
- Under reduced motion, the tag renders statically without animation.

## 2. TradePanel.tsx Audit
`TradePanel` provides a modal dialog for table offers and bank exchanges.
It shares one quantity draft between table trades and bank quotes.

### Dialog Semantics and Landmarks
- The dialog container sets `role="dialog"` and `aria-modal="true"`.
- `aria-labelledby="trade-title"` points to the `Trade` heading.
- The scrollable goods list has `role="region"` and `tabIndex={0}`.
- The region uses `aria-labelledby="trade-goods-title"` with visually hidden heading text.
- Subsections use `aria-labelledby` linking to `"Give"` and `"Get"` headings.
- The bank section groups controls inside `role="group"` with `aria-label="Bank & docks"`.

### Focus Management and Focus Trapping
- `useFocusTrap` manages modal focus lifecycle.
- Focus lands initially on the Close button when the panel opens.
- Tab and Shift-Tab cycle strictly through focusable elements inside the dialog.
- Pressing Escape closes the panel, plays `ui_back`, and returns focus to `tradeOpener`.
- When the panel closes, focus restores cleanly to the element that triggered it.
- When a user decrements a good to zero, its minus button unmounts.
- Focus then transfers automatically to the resource add button or scroll region.

### Form Controls and Labels
- Stepper add buttons use `aria-label={`More ${RESOURCE_LABEL[resource]} to ${side}`}`.
- Stepper minus buttons use `aria-label={`Fewer ${RESOURCE_LABEL[resource]} to ${side}`}`.
- `aria-describedby` links add buttons to live owned stock and current count.
- The quantity indicator uses the `<output>` element with an accessible label.
- Need toggles in `SeatNeeds.tsx` use `aria-pressed` to indicate selection state.

### Live Announcements
- The table offer preview element uses `aria-live="polite"`.
- The Bank quote preview element uses `aria-live="polite"`.
- Screen readers announce updated trade terms as cards change.
- Dynamic import errors in `LazyBoundary` render with `role="alert"`.

### Focus-Visible Outlines
- All interactive buttons receive `2px solid var(--ink)` outline on `:focus-visible`.
- The scrollable goods region displays a `2px solid var(--ink)` outline when focused.
- Outline offsets ensure rings remain visible against light card backgrounds.

## 3. Proof Verification Results
Three test suites were executed to verify accessibility and keyboard behavior.

| Test Script | Status | Coverage |
| :--- | :--- | :--- |
| `npm run seat-gains-prove` | PASS | Role, aria-label, positioning, reduced-motion, and DOM isolation. |
| `npm run trade-contrast-prove` | PASS | WCAG text contrast ratios (>= 4.5:1) across 3 viewports. |
| `npm run trade-tabs-prove` | PASS | Tab cycle, Escape key, focus restoration, live announcements. |

### Contrast Measurements
`scripts/trade-contrast-prove.mjs` confirmed compliance across 1280x720, 390x844, and 844x390 viewports.
All resource text labels meet or exceed the 4.5:1 WCAG AA threshold:
- Brick: 4.836:1 (unselected and active).
- Wheat: 4.605:1 (unselected and active).
- Stone: 4.777:1 (unselected and active).

### Keyboard Navigation Validation
`scripts/trade-tabs-prove.mjs` validated keyboard flows across four viewports.
The suite verified:
1. Close button receives initial modal focus.
2. Tab key navigates into the scrollable goods region.
3. Stepper controls allow full keyboard drafting without mouse interaction.
4. Unmounted minus controls return focus to connected add buttons.
5. Focus wraps inside the dialog without leaking to underlying elements.
6. Escape key dismisses the dialog cleanly.

## 4. Audit Conclusion
`SeatPublicGains.tsx` and `TradePanel.tsx` comply with accessibility and keyboard navigation standards.
Zero regressions or accessibility barriers were identified.
